# 🛰️ Hermes AI Assistant

## 🎯 Project Overview

Hermes is a personal AI assistant built to run entirely on my own hardware, accessible through Discord. Rather than relying on cloud infrastructure or complex tunneling setups, the design philosophy is simplicity: everything runs on a Dell XPS laptop I have dedicated to it, and I interact with it through a Discord bot interface.

The name Hermes reflects the role the assistant plays, acting as a messenger and orchestration layer between me, my data, and the tools I use every day.

## 🏗️ Architecture

### Hardware
Everything runs on a **Dell XPS laptop** set up as a local server. No Raspberry Pi, no Mini PC, no cloud compute. The laptop has an SSD with plenty of storage, which makes it a natural fit for running a local database alongside the AI stack.

### Interface: Discord
Instead of building a web interface or setting up Cloudflare tunneling, I connect to Hermes through **Discord**. The bot listens to a private channel, processes messages through the AI pipeline, and responds directly in chat. This keeps the setup simple, the interface familiar, and eliminates the need for any external network exposure.

### Memory: Honcho + Local Ollama
For persistent memory across conversations, I use **Honcho** as a SQL database backend. Honcho stores a history of past interactions on the laptop's SSD, and a local **Ollama** instance is used specifically to process and query that history, allowing Hermes to look back at what we've discussed previously and maintain context across sessions. Ollama here is scoped entirely to the memory layer, not general inference.

### AI Inference

The main reasoning layer connects to **Google's Gemini API**, using the Gemini model for all general inference and chat responses. Although the infrastructure runs locally on the Dell XPS, the AI model itself runs on Google's cloud via the API. The Gemini free tier covers everything the assistant needs, so there is no cost to run the AI layer. The local Ollama instance is reserved specifically for Honcho memory lookups and does not handle general inference.

## 📧 Newsletter Pipeline

Hermes generates and sends an automated weekly newsletter. The current production setup uses **Gmail SMTP** via **Himalaya**, a command-line email client that integrates cleanly with the rest of the local stack.

### Iteration History

| Version | Email Tool | Notes |
| :--- | :--- | :--- |
| v1 | Resend API | Easier initial setup but added an external dependency |
| v2 (current) | Gmail SMTP via Himalaya | Fully local config, no third-party email service |

The switch from Resend to Gmail SMTP was driven by the same philosophy as the rest of the project: reduce external dependencies and keep everything under my control.

### What the Newsletter Covers
The newsletter pulls together a weekly summary covering server health, recent activity, and any curated content I want to track. The content is generated by the LLM and delivered to my inbox automatically.

## 🔮 Future Ideas

### Scam Email Auto-Responder
One of the most interesting ideas I want to build out is an automated scam response system. Scammers frequently reach out to victims via email, and the idea is to have Hermes automatically detect incoming scam emails and respond to them, wasting the scammer's time and potentially protecting others. Since Hermes already has Gmail SMTP integration for outbound email, the pieces are largely already in place.
